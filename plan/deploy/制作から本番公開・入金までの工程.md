本番サーバーは依頼者から共有済みで、ファイルを更新できることも確認済み（ドメインも紐づいている）。

## STEP1｜サイト全体のテスト
表示・リンク・フォーム検証・レスポンシブ・ブラウザ・画像/PDF・メタ情報を確認して合格した。Edge は未実施。フォームのメール到達は STEP3 で確認する。
結果: [`specification/website/サイト全体テスト結果レポート_確認環境.md`](../../specification/website/サイト全体テスト結果レポート_確認環境.md)

テスト後にもサイトを変更している（A-15C の寸法図の差し替えなど）。STEP3 の前に、変更したページの表示を確認し直す。

## STEP2｜見積書の送付・承諾
確認環境での修正が際限なく続かないよう、依頼者確認の前に範囲を合意しておく。見積書には次を書く。

- 確認環境での修正の回数（上限）
- 公開後の不具合対応の期間（STEP7）
- 公開後の内容変更・追加の扱い（有償か無償か）
- 支払期日

チェック:
- [ ] 見積書を送付する（送付日: ）
- [ ] 承諾をもらう（承諾日: ）※メールなど記録が残る形でもらう

## STEP3｜確認環境（GitHub Pages）で依頼者確認
- [ ] 確認環境のURLを共有して確認を依頼する。PCとスマートフォンの両方で見てもらい、社内で使っているブラウザも聞く（Edge なら Edge で確認する）
- [ ] A-15C の高さが、寸法図の 37mm と仕様表の 36mm のどちらが正しいか答えてもらう
- [ ] フォームから 1 件テスト送信してもらい、FormSubmit から届く承認メールを依頼者に承認してもらう。承認後に発行されるエイリアスに `website/src/index.html` の `form action` を差し替え、もう一度送信してメールの到達を確かめる
- [ ] 指摘があれば修正し、再確認を依頼する（見積の回数の範囲で）
- [ ] 確認OK（日付: ）※メールなど記録が残る形でもらう

## STEP4｜請求書のPDF送付
- [ ] 請求書を作ってPDFにし、支払期日を書いて送付する（送付日: ）

## STEP5｜入金確認
- [ ] 入金を確認する（入金日: ）。支払期日を過ぎたら依頼者に連絡する

## STEP6｜本番サーバーへのアップロード
入金確認後に行う。詳しい手順: [`specification/deploy/FTPデプロイ手順.md`](../../specification/deploy/FTPデプロイ手順.md)

- [ ] `website/public/robots.txt` と `sitemap.xml` の URL を本番ドメインに書き換える（ビルドでは置き換わらないため、ビルドの前に行う）
- [ ] 本番用にビルドする: `cd website && npm ci && BASE_PATH=/ SITE_URL=https://本番ドメイン/ npx vite build`
- [ ] サーバーに既存のファイルがあれば、ダウンロードしてバックアップする
- [ ] `website/dist/` の中身を FTP/SFTP でアップロードする
- [ ] 手順書の「2-5. 公開後のチェックリスト」をすべて確認する（フォームのメール到達と `thanks.html` への遷移を含む）
- [ ] GitHub Pages を停止するか、STEP7 の確認用に残すなら `noindex` を付ける（手順書の 2-6）
- [ ] 公開を依頼者に連絡する（公開日: ）

## STEP7｜公開後の不具合対応
STEP2 で決めた期間内に見つかった不具合のうち、本番環境が原因のものと、STEP3 で確認した内容と違うものが対象。内容の変更や追加の要望は、下の「運用」で扱う。

- [ ] 不具合の連絡があれば修正して再アップロードする
- [ ] 対応期間の終了（日付: ）
