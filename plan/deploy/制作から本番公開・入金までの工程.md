表示・リンク・フォーム検証・レスポンシブ・ブラウザ・画像/PDF・メタ情報を確認して合格した。
結果: [`specification/website/サイトのテスト.md`](../../specification/website/サイトのテスト.md)（テストの項目・方法・結果は、本番環境の分もこのファイルにまとめる）

テスト後に変更したページ（A-15C の寸法図、問い合わせ欄のメールアドレス、リポジトリ構成の再編）と、STEP1 で未実施だった Edge での表示を 2026-11-21 に確認した（issue #23）。この確認で見つかった、ヒーローの背景写真が切り替わらない問題は修正した。

## STEP2｜見積書の送付と、確認環境での依頼者確認
見積書と確認環境のURLを同時に送る。

- [x] 見積書（PDF）と送付メールの文面を作る（作成日: 2026-11-21）。どちらもリポジトリの外に置く
- [ ] 見積書と確認環境のURLを送る（送付日: ）
  - PCとスマートフォンの両方で見てもらう。依頼者は IT に詳しくないため、確認の依頼はこれと次の 1 点に絞る
  - A-15C の高さが、寸法図の 37mm と仕様表の 36mm のどちらが正しいか答えてもらう
  - ブラウザは聞かない。Edge での表示はこちらで確認済み（STEP1 を参照）
  - 問い合わせ欄のメールアドレス（`mitsuwa@iris.eonet.ne.jp`）は旧サイトでも使っていたため、確認を依頼しない
- [ ] 指摘があれば修正し、再確認を依頼する（見積書の修正回数の範囲で）
- [ ] 見積の承諾と確認OKをもらう（日付: ）※メールの返信など記録が残る形でもらう。署名・押印はもらわない

見積書に書くこと:
- 宛名、発行日、見積番号、発行者の名称・住所・連絡先
- 件名と作業範囲（対象ページ、問い合わせ欄などの内容）と、含まないもの（サーバー・ドメインの費用、写真撮影など）
- 金額の内訳（項目・数量・単価）、小計、消費税、合計
- 修正の回数の上限と、超えた場合の扱い
- 公開予定日
- 公開後の不具合対応の期間（STEP6）と、内容の変更・追加の扱い（有償か無償か）
- 支払条件（請求のタイミング、支払期日、振込手数料の負担）
- 見積の有効期限

## STEP3｜請求書のPDF送付
- [ ] 請求書を作ってPDFにし、送付する（送付日: ）

請求書に書くこと:
- 宛名、請求日、請求書番号、発行者の名称・住所・連絡先
- 件名と、承諾された見積書の番号
- 明細（項目・数量・単価）、税率ごとの合計と消費税額、請求金額（税込）
- 支払期日と振込先（銀行名・支店名・口座種別・口座番号・口座名義）
- 適格請求書発行事業者の登録番号（登録している場合。依頼者が仕入税額控除を受けるのに必要）

## STEP5｜本番サーバーへのアップロード
入金確認後に行う。詳しい手順: [`specification/deploy/FTPデプロイ手順.md`](../../specification/deploy/FTPデプロイ手順.md)

- [ ] [`FTPデプロイ手順.md` の「2-1. 事前準備」](../../specification/deploy/FTPデプロイ手順.md#2-1-事前準備初回のみ)の残りの項目（接続方式、HTTPS、接続情報の登録）を確認する
- [ ] `website/public/robots.txt` と `sitemap.xml` の URL を本番ドメインに書き換える（ビルドでは置き換わらないため、ビルドの前に行う）
- [ ] 本番用にビルドする: `cd website && npm ci && BASE_PATH=/ SITE_URL=https://本番ドメイン/ npx vite build`
- [ ] サーバーに既存のファイルがあれば、ダウンロードしてバックアップする。接続確認で置いた仮の HTML は削除する
- [ ] `website/dist/` の中身を FTP/SFTP でアップロードする
- [ ] [`サイトのテスト.md` の「3. 本番環境：公開後のテスト」](../../specification/website/サイトのテスト.md#3-本番環境公開後のテストstep5)をすべて確認し、結果を書く（問い合わせ欄のメールリンクの確認を含む）
- [ ] GitHub Pages を停止するか、STEP6 の確認用に残すなら `noindex` を付ける（[`FTPデプロイ手順.md` の 2-6](../../specification/deploy/FTPデプロイ手順.md#2-6-本番公開後の-github-pages-の扱い)）
- [ ] 公開を依頼者に連絡する（公開日: ）

## STEP6｜公開後の不具合対応
見積書で決めた期間内に見つかった不具合のうち、本番環境が原因のものと、STEP2 で確認した内容と違うものが対象。内容の変更や追加の要望は、下の「運用」で扱う。

- [ ] 不具合の連絡があれば修正して再アップロードする
- [ ] 対応期間の終了（日付: ）
