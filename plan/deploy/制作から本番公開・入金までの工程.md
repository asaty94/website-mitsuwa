## STEP1｜サイト全体のテスト ✅
表示・リンク・フォーム検証・レスポンシブ・ブラウザ・画像/PDF・メタ情報を確認して合格（Edge は省略）。フォームの実メール到達は STEP6 で確認する。
結果: [`specification/website/サイト全体テスト結果レポート_確認環境.md`](../../specification/website/サイト全体テスト結果レポート_確認環境.md)

## STEP2｜確認環境（GitHub Pages）で依頼者確認
- [ ] 確認環境のURLを共有して確認を依頼する
- [ ] A-15C の高さ（寸法図 37mm／仕様表 36mm）の差異も確認してもらう
- [ ] 指摘があれば修正し、再確認を依頼する（OKが出るまで繰り返す）
- [ ] 確認OK（日付: ）※OKはメールなど記録が残る形でもらう

- [ ] 見積書を送付する（送付日: ）
- [ ] 承諾をもらう（承諾日: ）※メールなど記録が残る形でもらう

- [ ] 請求書を作ってPDFにし、送付する（送付日: ）

## STEP5｜入金確認
- [ ] 入金を確認する（入金日: ）

## STEP6｜本番サーバーへのアップロード
入金確認後に行う。詳しい手順: [`specification/deploy/FTPデプロイ手順.md`](../../specification/deploy/FTPデプロイ手順.md)

- [ ] 本番用にビルドする: `cd website && BASE_PATH=/ SITE_URL=https://本番ドメイン/ npx vite build`
- [ ] `website/public/robots.txt` と `sitemap.xml` の URL を本番ドメインに手で書き換える（ビルド時に置換されないため）
- [ ] FormSubmit の確認メールを承認し、`website/src/index.html` の `form action` を発行されたエイリアスに差し替える
- [ ] `website/dist/` を FTP/SFTP でアップロードする
- [ ] 本番URLで表示・リンク・画像/PDFを確認する
- [ ] フォームから 1 件テスト送信し、メールの到達と `thanks.html` への遷移を確認する
- [ ] 公開を依頼者に連絡する（公開日: ）

## STEP7｜公開後の不具合対応
対象は、公開から一定期間内（期間は見積時に決める）に見つかった、本番環境が原因の不具合や確認済みの内容との違い。内容の変更や追加の要望は、下の「運用」で別に扱う。

- [ ] 不具合の連絡があれば修正して再アップロードする
- [ ] 対応期間の終了（日付: ）
